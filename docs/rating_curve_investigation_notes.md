## TL;DR（30 秒版）

- **起因**：审稿人质疑「多任务模型只是在学水位→流量的率定曲线（h→Q），不是真正的数据替代」。
- **核实结果**：86 个研究流域里 82 个的径流确由 USGS stage-discharge 曲线从水位换算；官方曲线 + 实测水位的中位 NSE = **0.9918**，≈ 恒等式（Q 基本是 h 的确定性函数）。
- **基线不弱**：项目的分箱率定基线换 3 种更复杂形式（插值/幂律）都没有提升；两阶段路径换官方曲线结果几乎不变（0.54 vs 0.55）。
- **瓶颈定位**：h→Q 映射接近恒等（0.99），瓶颈完全在「从气象预测水位」（0.99 → 0.55 掉的 0.44 全在这一步）。
- **论文主结论不用改**；D6 那条「率定路径极依赖流量量级」其实**被印证了**（三点一线），只需在 §10/Fig 6 补一句「官方曲线 = 保留量级信息的上界」。
- **未完成**：①F 盘掉线导致 14 个候选非率定流域的 h→Q 松紧检验没跑；②汇报文档差「外部有效性」一节；③`source_of_truth_v2.md` 两处旧表述待改（等拍板）。

## 1. 背景：论文当前框架（重要前提，别按旧印象）

论文主命题已从 **H2Q（水位→流量的级联）** 改为 **数据替代**：部分流域完全没有径流观测、只有水位观测时，双头多任务 LSTM 能改善这些流域的径流预测。H2Q 已退到附录（结论「级联本身没用」）。

率定曲线在论文里的角色是**研究问题 #4 的对照组**（Methods §10、Results §4.4 / Fig 6），要支撑的结论原为：

> 显式率定路径（预测水位 → 区域化率定曲线 → 径流）**不能复制**该效应，且**极依赖已知流量量级**。

| 双头 | 0.6194 | 0.5921 | −0.027 |

四配置（base / physical / L480+extended / L480+physical+extended）双头领先率定路径 +0.032 / +0.143 / +0.039 / +0.181，全部 p<10⁻⁴。D7 特别标注「率定路径并非弱基线」（base 70% 下 0.538 反超单任务 Q 的 0.445）。

## 2. 三个「率定曲线」概念（混在一起就乱）

| | 是什么 | 在哪 |
|---|---|---|
| **A. USGS 官方 rating** | 真实物理单位的水位(ft)→流量(cfs) 查表，USGS 拿来产流量数据 | 网上 NWISweb，项目里**没用** |
| **B. 项目率定基线** | 从数据拟合的查找表，**只在评估时当对照** | `src/evaluation/rating_baseline.py` |
| **C. H2Q/wl2d 模型** | 神经网络学的水位→流量，论文主角（已退附录） | `src/training/multi_task_lstm_wl2d.py` |

**B 的实现 = 「分箱求均值」**（非拟合方程、非幂律、无参数，核心 14 行）：
- `fit_rating(h, q, n_bins=50)`：把该流域训练期配对 (h, q) 按 h 等样本量切成 50 箱，每箱取 q 均值 → 50 个数的查找表。
- `apply_rating(fit, h)`：`np.searchsorted` 查表，新水位落哪个箱就返回哪个箱均值。
- 所以它是个 **50 级阶梯函数**；h、q 都是 **z-score 归一化**（为了跨 86 个量级悬殊的流域合并成一条曲线）。

B 之上有三个分析：`rating_stability`（时间稳定性，86 条逐流域曲线）、`regionalized_rating`（跨流域一条，上界参考）、`two_stage_baseline`（真正的竞争对手，先预测水位再套曲线）。

## 3. 五个核心发现

### 发现一：径流的数据生成过程（Q ≈ f(h)，近乎恒等式）

86 个流域核查（`src/evaluation/usgs_rating_metadata.py`，查 USGS NWISweb ratings depot）：

| | 数量 |
|---|---|
| 有 stage-discharge 曲线（`TYPE="STGQ"`） | **82** |
| 无曲线 | 4 |

4 个无曲线中，3 个是停测站（`01018000` 2015、`01021200` 2012、`01089100` 2022，停测后曲线被撤下），`01100561` 仍在运行但三类文件全空，原因无法从公开接口判定。

**官方曲线 vs 项目分箱曲线**（`src/evaluation/official_rating_check.py`，物理量口径，82/86 可比）：

| 口径 | 均值 NSE | 中位 NSE |
|---|---|---|
| **USGS 官方曲线**（物理量、当前版） | **0.9623** | **0.9918** |
| 项目分箱曲线（同期自拟合，上界） | 0.8898 | 0.9264 |
| 项目分箱曲线（训练期拟合→测试期） | 0.8583 | 0.8939 |

官方比分箱高 0.104，82 个里 81 个官方更高。**中位 0.9918 = 恒等式**：CAMELSH 的径流就是 USGS 拿这条曲线从水位算出来的，我们只是把计算过程倒推了一遍。单位换算也印证：CAMELSH 是 m / m³/s，官方是 ft / cfs，换算后流量范围 71.3–49400 cfs 几乎完全重合于折点 75.5–48400 cfs。

官方 NSE 最低的站是 `01101000`（−0.735，6 折点、当前版不适用测试期），而分箱曲线在该站反而有 0.935。

**官方曲线形式**：分段幂律 $Q = C_i(h-h_0)^{\beta_i}$，对数空间线性内插，4–15 个折点 + 一个偏移量 h₀（有效零点）。示例 `01085000`（Contoocook River，5 折点）四段 β 极差仅 0.0024，本质单一幂律 β≈2.96；`01017000`（Aroostook）β≈2.07。

### 发现二：分箱基线不是弱基线

**A. 三种更复杂形式都没能提升**（26 保留流域 62.5 万对拟合，60 留出评估，实测水位口径）：

| 率定形式 | 均值 NSE | 中位 | 与现用之差 | 配对检验 |
|---|---|---|---|---|
| **50 级阶梯（现用）** | **0.8618** | 0.8975 | — | — |
| 单调保形插值 PCHIP | 0.8605 | 0.8935 | −0.0013 | p=0.30 不显著 |
| 箱中心线性内插 | 0.8394 | 0.8659 | −0.0224 | p=0.0002 显著更差 |
| 对数空间分段幂律 | 0.8384 | 0.8679 | −0.0234 | p=0.0002 显著更差 |

**B. 两阶段路径换官方曲线，结果几乎不变**（base 配置，2 种子，81 流域）：

| 路径 | 均值 | 中位 |
|---|---|---|
| 两阶段 + 自拟合分箱曲线 | 0.5362 | 0.5467 |
| 两阶段 + **官方曲线** | 0.5238 | **0.5528** |

均值 −0.0124，中位 +0.0070，官方更高 47/81，基本五五开。

**为什么分箱最优（理论依据）**：NSE 最小化的预测就是条件期望 E[q|h]，分箱取均值正是它的非参数估计，直接估计了要优化的量；幂律在 z-score（有负值）下 log 无定义；跨流域混合后 β 从 2.07 到 2.96 不等、无单一参数形式。分箱在最高一箱是平的、外推天然截断，反而鲁棒。

### 发现三：瓶颈完全不在 h→Q 映射，而在预测水位

| 口径 | 输入 | NSE 中位 |
|---|---|---|
| 官方曲线 + **实测**水位 | 实测水位 | **0.9918** |
| 官方曲线 + **预测**水位 | 气象 | 0.5528 |
| 自拟合曲线 + 预测水位 | 气象 | 0.5467 |
| 双头 | 只有气象 | 0.5705（均值） |

从 0.99 掉到 0.55，**掉的那 0.44 全部来自「预测水位」这一步**。所以双头相对单任务的增益不可能来自「学会了 h→Q」（那步太简单、已近恒等），只能来自 H 标签帮它学到了更好的水文状态表示。

**反直觉细节**：官方曲线配**预测**水位反而更脆——β≈2.96 把水位相对误差放大约 3 倍（$dQ/Q \approx \beta\,dh/(h-h_0)$），`01101000` 掉到 −1.10；分箱曲线高位截平反而稳。所以「更精确的曲线」在输入有噪声时不一定是优势。

### 发现四：量级依赖（D6 结论经过反复，最终结论见下）

四配置完整对比（均值 NSE）：

| 配置 | 单任务径流 | 两阶段+自拟合 | 两阶段+**官方** | 双头 |
|---|---|---|---|---|
| base | 0.4409 | 0.5362 | 0.5312 | **0.5695** |
| physical | 0.4065 | 0.3767 | **0.5312** | 0.5228 |
| L480+extended | 0.3059 | 0.5775 | 0.5791 | **0.6167** |
| L480+physical+extended | 0.3662 | 0.4052 | **0.5791** | 0.5896 |

官方曲线在 base 和 physical 是**同一个数**（0.5312 / 0.5791）——它直接产出物理流量，不碰径流归一化口径，所以「去掉流量量级」对它无效。乍看 D6「极依赖已知流量量级」站不住。

**但这是错的**。官方曲线的折点数值 `(0.5009 ft, 75.54 cfs)…(13.85 ft, 48400 cfs)` **本身就编码了这条河的量级**，且由该站几十年成对实测径流定出——量级信息被「烧进曲线里」，physical 口径（只剥外部传入的径流统计量）剥不掉它。

**三点一线证据**（L480+extended 口径）：

| 量级信息 | 路径 | NSE |
|---|---|---|
| 保留（实测统计量） | 自拟合 + observed | 0.5775 |
| 保留（烧在折点里） | 官方曲线 | 0.5791 |
| **剥离**（area×p_mean 回归推算） | 自拟合 + physical | **0.4052** |

前两行保留量级结果几乎一样（0.577 vs 0.579），剥离就塌 0.17。**D6 结论被印证了，不是被推翻**。

**最终结论（论文表述）**：
- 论文结论**不用改**。合法的率定路径在 physical 下就是 0.4052，双头 0.5896 领先 +0.184，与原文一致。
- 只需在 §10 或 Fig 6 图注**加一句**：官方率定曲线可视为保留量级信息的上界，其表现与 observed 口径的自拟合曲线相当（0.579 vs 0.578），进一步说明该路径的表现由流量量级而非曲线形状决定。
- 官方曲线在零径流观测的设定下**按定义不可得**（有曲线 ⟺ 有过大量实测径流 ⟺ 不需要预测），所以它只是「作弊的天花板」，不是合法基线。双头在不知留出流域任何径流信息时与它打平（physical 下 +0.011），这个「打平」本身就是结论。

### 发现五：非率定流域筛选（找 index-velocity 对照）

**概念澄清**：USGS 连续流量没有一种是「直接测量」的，全由某可测变量经率定关系换算。方法码 `SWQC` 类共 15 个：`QSTGQ`（水位→流量，最常见）、`QVELO`（index-velocity，流速+水位）、`QGATE/QDAM/QCLVT`（闸/坝/涵洞）、`QSLPQ/QSLPA`（比降）、`QSVEL/TS228`（表面流速）。人工实测（ADCP/缆车）是直接测的，但只是每年十几次的离散点，不构成连续记录。所以准确问法是「有多少**不用 stage-discharge**」。

**2231 站全量核查**（强迫∩水位的站）：

| | 站数 | 占比 |
|---|---|---|
| 有 stage-discharge 曲线 | **1836** | 82.3% |
| 无当前曲线 | 395 | 17.7% |

1836 个有曲线的站 `TYPE` **全部是 STGQ**。395 个无曲线的拆解：312 已停测 / 20 查不到径流 / **62 仍在运行却无曲线（潜在非 STGQ）** / 1 请求失败。62 个里 14 个水位覆盖达标、可用于建模。

**14 个候选流域**（`results/summary/nonrating_basin_candidates_run1.csv`）：

```
01100561 01189000 02322800 02365769 02366996 02407000 03198000
05422600 06843500 06890900 06893620 06893890 07154500 07230500
```

面积跨度 24–37413 km²（不全是大河，地理分布也散），这是好事——可挑面积匹配的站做配对比较，拆开「非率定」与「受调节大河」两个混淆因素。

**公开接口的硬限制**：站级方法编码不对外——`time-series-methods` 查 `QVELO`/`QGATE` 返回 0 条（`QSTGQ` 有记录），ratings depot 只能看「有没有水位-流量曲线」，无法识别「有曲线但实际用 index-velocity」的站。所以只能引文献：index-velocity 约 470 站（Levesque & Oberg 2012，2011 数据），连续测流站 8705、连续水位站 12165、只有水位没有流量 3460（USGS NSN，2024-10）。

**为何对照组这么难凑**：CAMELSH 建在 **GAGES-II** 之上，而 GAGES-II 按「长期连续流量记录 + 少人类干扰」筛的**河流站**集合，天然排除 index-velocity 的典型场景（潮汐河口、大河低比降段）。验证过河口类站（`site_type_code=ES`）与 CAMELSH 交集 = 0。所以 82.3% 全 STGQ 是数据集构造决定的，不是巧合。

**重要陷阱（曾走弯路）**：最初用「index-velocity 只用于一个水位对应多个流量的站」论证对照组有选择偏差，后查原文（Levesque & Oberg 2012）发现引错——原文是 "**can be used** at locations where stage-discharge methods are used, but **especially appropriate** when..."，是「尤其适用」不是「只用于」。选择偏差只是**部分**的，论证站不住。最终理由改为：**公开接口无法识别流量计算方法，故无法构造对照组**（这是论证不掉的真实局限）。
